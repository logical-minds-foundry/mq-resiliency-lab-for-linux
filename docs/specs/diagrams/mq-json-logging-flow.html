MQ diagnostic logging — everything to JSON in journald

Every MQ surface is configured to emit single-line JSON into the operating-system journal. That JSON-in-the-journal boundary is the portable deliverable — vendor-neutral, manageable, and the same on every arm. Whatever ships and stores it downstream (here: Alloy → Loki → Grafana) is site-specific and swappable; a client site can substitute its own collector without touching anything to the left.

Why the boundary matters. The work of this effort stops at JSON-in-the-journal. Once MQ diagnostics are structured JSON in journald (+ one file for mqweb), they are manageable by any tooling — journalctl, rsyslog forwarding, a SIEM, or the lab's Alloy/Loki. Nothing to the left changes when the transport changes.
The legacy text logs are ignored, by decision. MQ always also writes the multi-line AMQERRnn.LOG stanza files; they cannot be turned off. We neither ship nor parse them — the JSON surface carries the same events in a line-oriented form. No stanza-block parser, ever.
